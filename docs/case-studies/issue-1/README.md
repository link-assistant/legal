# Case study: official legal sources and a deterministic assistant

Research and bounded experiments performed on 18 October 2026 for [issue 1](https://github.com/link-assistant/legal/issues/1) and [PR 2](https://github.com/link-assistant/legal/pull/2).

## Outcome and scope

The implementation supplies a JavaScript library, CLI, read-only HTTP API, Docker image, collected-data browser explorer, source registry, collection/persistence primitives, scheduled collection scaffolding, real associative representations, source-bound rule evaluation, and tests. The sample consists of four official-source records in three jurisdictions, with raw evidence and hashes. It does **not** establish all-law/all-language coverage or automatic understanding of all laws. Several original acceptance criteria remain blocked or unfinished, as mapped below. The PR must remain unmerged until those criteria are resolved or its scope is explicitly changed.

The current `doublets-rs` direction involves a native runtime; a JS-only prototype uses associative networks and content-addressed records instead. IndexedDB and larger graph indexes would help scale browser data later, but are not claimed as implemented dependencies. Current search is deterministic local lexical retrieval.

## Formal AI and dependency integration

Formal AI source: `fd5bfaced85262a51b341fb2b25c79e507423ca3`, `js/agentic/crate/relative_meta_logic.mjs`, upstream SHA-256 `332217acd917fb61fc58cbe8e2762eb6166ab055a4c9f63c1e10c1eb8e2b1a25`. The build refuses source checksum drift and patch context drift. Only the patch and bootstrap metadata are versioned; generated dependency code is ignored in Git and included in distribution artifacts.

The patch adds categorical evidence status, preserving contradictions and unknowns instead of describing a probability as legal proof. Source retrieval's assessment explicitly concerns the existence of matching text. Reviewed-rule inference is separate and requires exact source spans, edition hashes and supplied facts.

## Official-source research and access evidence

The probes in `experiments/probe-*.mjs` use finite byte/time budgets and preserve responses separately from interpretation. `data/live-access.log.gz` contains observed results. Access failures are observations of this environment, not assertions that a government service is globally unavailable.

- The [US Code download page](https://uscode.house.gov/download.html) exposes per-title USLM ZIPs. The older `/download/download.shtml` probe produced an error page; the implementation uses the verified modern page. [GovInfo bulk data](https://www.govinfo.gov/bulkdata) complements statutes with structured regulations, with bounded recursive directory traversal and persisted resumable cursors. A live two-page check reached the 2026 catalog and retained 41 pending paths; this does not establish full CFR coverage.
- [EUR-Lex reuse guidance](https://eur-lex.europa.eu/content/help/data-reuse/reuse-contents-eurlex-details.html?locale=en) describes data reuse, and [Cellar's documentation](https://op.europa.eu/en/web/cellar) describes machine-readable multilingual publications. Cellar includes publications beyond legislation, so metadata must be filtered and actual content resolved. EU legislation is only part of Europe's law.
- The NPC root returned a JavaScript shell. Inspection of its published app bundle confirmed a POST list endpoint; a shell is not legal text and is not an access-denial response. Actual constitutional texts were collected from `www.gov.cn` and `english.www.gov.cn`; the English 2014 publication predates 2018 amendments and is labeled historical.
- India Code returned a denial page for the tested act; further catalog/Legislative Department probes timed out. [The Legislative Department's document index](https://www.legislative.gov.in/documents) identifies constitutional editions and regional versions. Their existence does not establish successful collection from this environment.
- Pravo publication/IPS and Kremlin alternate probes timed out. Old repository loader code is evidence of a previous mechanism, not proof that the present list/detail API works.
- Matsne supplied the English Constitution through its `www` origin during recovery; original-language and edition-specific later requests returned short denial responses. The collector checks the actual law-body selector rather than treating navigation as content.

## Redistribution and publisher load

This is a source-by-source investigation, not a blanket legal clearance. Legislation text and a site's photographs, branding, database structure and third-party annotations can have different terms. The software's Unlicense does not relicense collected source material.

[China's NPC-published copyright text, Article 5](https://en.npc.gov.cn.cdurl.cn/2020-11/11/c_674691_2.htm) and [Georgia's copyright law, Article 8](https://matsne.gov.ge/en/document/download/16198/10/en/pdf) exclude specified official legal documents and translations from copyright protection. Those provisions support the bounded text samples, while website presentation/other materials require separate consideration. The raw HTML is preserved as audit evidence, not advertised as an unrestricted reusable website archive. [US Archives policy](https://www.archives.gov/global-pages/privacy.html) and official-document provenance should be checked for each resource; do not assume all US state or third-party material has federal-government status. [The EU Publications Office notice](https://op.europa.eu/en/web/about-us/legal-notices/publications-office-of-the-european-union-copyright) directs reusers to resource-specific notices, including EUR-Lex conditions. India and Russia bulk distribution terms were not verified through the blocked live sources, so permanent redistribution is unapproved in the example configuration.

No broad crawl was launched. Bulk/structured endpoints are preferred; per-origin delays, caching and finite run budgets reduce repeated demand. A permanent external corpus repository must separately verify publisher terms, corpus/language scope, missed updates, historical editions, deletion/repeal semantics, resource budgets and successful complete discovery before claiming complete coverage.

## Remaining solution plan and acceptance evidence needed

1. Establish inventories for every requested country/subnational jurisdiction, every European national/non-EU publisher and each government-supported publication language. Reconcile actual discovered IDs and available translations against those inventories; a hard-coded language list is not evidence of completeness.
2. Obtain successful authorized live responses for the blocked publishers, validate current schemas, validate NPC detail contracts and full GovInfo inventory coverage, integrate source-specific document linking, and preserve raw fixtures. Add full-crawl pagination/resumption and independent count checks. Retain access failures visibly until resolved.
3. Add reviewed OCR/text quality checks for scans and language-specific segmentation/terminology. A PDF with extractable but corrupted legacy-font text must not pass as reliable language content merely because letters exist.
4. Model amendments, effective dates, territorial/subject scopes, citations, definitions, exceptions, priorities and conflicts. Produce reviewed legal rule corpora tied to source editions. Prove semantic equivalence for supported transformations; syntax round trips alone are insufficient.
5. Evaluate real legal questions across all target jurisdictions with expected answers and source proofs. Define a bounded, testable capability target. There is no evidence here supporting a universal “virtually any legal question” guarantee, so that criterion remains unmet.
6. Pages has been deployed from the prepared branch and its [public URL](https://link-assistant.github.io/legal/legal/) verified in Chromium. Keep deployment verification current after changes. Activate the separate permanent collection repository only after publisher and distribution reviews. This PR remains unmerged; no acceptance requirement is silently replaced by an upstream report or a passing test.

## NPC contract and access update

A bounded inspection of the current publisher JavaScript and two-item list response identified the current POST payload, `rows` result array and `bbbs` edition IDs. The old GET/provisional schema failed a reproducing test; POST discovery now preserves raw evidence separately for each payload. Metadata-only rows remain unresolved resources rather than fabricated laws. A second regression test verifies that a publisher-wide robots prohibition prevents the POST request entirely.

The observed [NPC robots policy](data/npc-robots.txt) disallows all automated collection. One initial bounded metadata inspection returned 30,995 catalog entries in total, not 30,995 collected laws; only two metadata rows were fetched. Its probe initially failed to stop after reading robots. That experiment has been corrected to stop, and production collection already enforces the policy. No further NPC content requests were made after identifying this restriction. The response schema/hash and probe logs are archived. Unrestricted automatic collection from this publisher is blocked pending publisher permission or a permitted alternative source. Other official Chinese pages supplied the existing Constitution samples; those samples do not establish complete Chinese coverage.
